# FLD-03 documentary quality and safety

Online source package for inspections, deficiencies, safety observations, restricted incidents and documentary permit records. No offline capture, provider call, finance, payroll, award, external delivery, professional approval, medical advice or actual authority to perform hazardous work is implemented.

Ordinary `record` headers/revisions/decisions and restricted `incident` headers/revisions/decisions use six separate native DocTypes. A seventh immutable DocType registers evidence that is restricted before canonical source creation. Generic native projections are closed; all Project duties must be explicitly granted. `quality.read/write/check/close`, `safety.incident.read/write/check/close` and `safety.incident.evidence.manage` are separate duties. Project administration implies none of them.

A draft is submitted, checked by another canonical Person, then closed by a third Person. A closed record requires an explicit successor and amendment reason; the original and its exact decisions remain unchanged. Closure binds every specified closure item to current exact source evidence, the checked revision digest and the independent checking Person. A historical readable submission may be returned for correction; new return evidence still needs current ingest rights. New effects and replay reads recheck current identity, duties and evidence rights.

Source resolution reuses FLD-01's bounded original-byte, source metadata and rights admission: at most 32 exact revisions/64 MiB per package, with complete rights-parent prelocking. There is no OCR, image interpretation, engineering certification or unit/rate inference.

Sensitive incident evidence uses the distinct private upload action. It requires incident evidence management and document write/rights management, exact current permission evidence and an authored rights basis. A repository wrapper inserts the immutable restriction before the canonical document or bytes exist in the transaction. Known ordinary duplicate bytes and existing document reclassification are rejected. A separate current content-rights policy is still required before the upload can be ingested into an incident. Existing ordinary non-sensitive Field sources remain reusable through an explicit list of exact shared revision IDs and an authored non-sensitive statement. The software does not classify the semantic content of that statement.

Incidents and private uploads create no ordinary Project activity event. Their own restricted immutable revision/decision lists retain chronology. Private sources, source-rights derivatives, lifecycle standing, canonical downloads, preview, citation, search and native list/count paths must use all provided integration fragments. Private source registration cannot be deleted, renamed or declassified through this package. Site/database administrators retain their separately controlled operational authority.

All new source files are additive. Shared hook, capability, default-grant exclusion, migration, command receipt, history, document-control and API/OpenAPI edits are external fragments in `docs/framework/fragments/fld03-quality-safety`; they have not been applied by this source lane. A partial integration is not a releasable privacy boundary.

26 focused host tests pass. The four native qualification cases are prepared, not executed. Source fixtures do not establish MariaDB transaction/locking, File deduplication, migration/controller behavior, authenticated HTTP/CSRF/session behavior, runtime concurrency, browser acceptance, accessibility, production performance or operational identity. Retrospective source migration, declassification, source duplication by an authorized reader and simultaneous ordinary/private duplicate-hash admission remain outside the verified boundary. Native release must prove the registration/File rollback and duplicate-admission behavior before enabling private uploads.
