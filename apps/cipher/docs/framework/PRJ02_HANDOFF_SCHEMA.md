## One canonical handoff

`Cipher Award Handoff` is the single Company-origin aggregate, with immutable `Cipher Award Handoff Revision` plans and one immutable completed adoption snapshot. It is not a new project/customer/order master. The aggregate reserves Company/Pursuit/Opportunity uniqueness before planning and binds its current revision/digest; the registered action `award.project.create.v1` reviews that exact revision/digest. Completed adoption is immutable and permits no later working revision. Its UUID and exact canonical JSON digest bind the following fields. Every indexed projection must equal its JSON field; unknown or missing fields fail integrity validation.

The Company abilities are exactly `commercial.award` and `project.team.delegate`. The requester must have both award authority and current explicit delegation authority for every selected Project ability; review/execute packets never imply those abilities. The sorted participant set includes requester, reviewer, explicit delegator and every team Person before identity/Company locks. An added or changed participant requires fresh planning.

`Cipher Award Line Adoption` is an immutable child/projection of that same handoff, never another commercial or price master. Each row binds `id` (UUID), `handoff`, `company`, `pursuit`, `issue`, `proposal_revision`, `proposal_line_id`, `project`, `contract`, `sales_order`, `sales_order_item`, `item_code`, complete qualified `unit` record, exact `quantity`, `rate`, `amount`, `currency`, rational `conversion_factor={numerator:'1',denominator:'1'}`, and `native_line_digest`. Uniqueness is `(company,pursuit,proposal_line_id)` and `(issue,proposal_line_id)`, with one destination order-item per adoption. The handoff's complete selected Issue line UUID set must equal the adoption set; unselected alternates are absent. Source-line ordering and native `idx` never establish identity.

Each selected Issue line already contains exact authored quantity/rate/amount, qualified UOM revision and persisted original Item facts. Award cannot silently replace a nonempty issued Item with another Item. A freeform issued line needs an explicit reviewed existing Item mapping and current qualified stock UOM; initial support admits only nonstock sales Items, exact 1:1 UOM, no tax, discount or FX. All native controller defaults are reconciled after save; unsupported precision/defaults roll the entire effect back.

Budget adoption is separate from selling price. Funded `budget_lines` cover only included accepted estimate components, using stable `(estimate_line_id,component_id)` identities and their exact already-rounded `components[].allocated_amount` and `cost_type`. Retain excluded `included=false` alternatives as source lineage without funding them. Indirect and contingency adjustments each receive a separate allocation keyed by their accepted adjustment UUID and exact accepted `amount`; no artificial quantity or component is inferred. Every allocation binds its acceptance ID/digest, stable budget-line UUID, WBS leaf and canonical Company cost-code/type identity/revision. Their sum must equal accepted direct + indirect + contingency = accepted total exactly, without rerounding or repricing. A budget never substitutes proposal revenue for estimate cost. `wbs_nodes` have stable UUID/code/parent/title and leaf flags; cycle, orphan and cross-Project links fail. Canonical Cipher Cost Code/Cost Type masters are authorized local prerequisites from framework §6 to implement after the checkpoint. Existing EST free-text `cost_code` remains descriptive input until explicitly mapped to that authority.

## Integrity classifier for FIN

The selected trusted internal function is `recognize_award_sales_order(*, company, customer, sales_order_id, own_contract_id=None)`. It returns typed recognized-own, recognized-other or unqualified standing plus an opaque watermark. The database already holds the exact Customer mutex and uses current locking reads; there is no actor parameter or optional nonlocking mode. It must not acquire Company, foreign Project or UOM locks after Customer. Immutable handoff/consumption/native equality is an internal bounded integrity check; it conveys no foreign Project/source access. Own contract/award/source/native reads remain a separate mandatory caller authorization boundary before mutation. Unknown/ambiguous/forged/mismatched lineage is unqualified; public admission publishes no foreign IDs/counts.

Native scan overflow fails closed before any recognized exemptions. The current 200-row bound uses `LIMIT 201` as an overflow sentinel; observing that sentinel refuses classification rather than filtering it and overlooking an unknown 202nd row.

The predicate requires the exact immutable handoff digest, registered independent grant/consumption, both full-lineage uniqueness reservations, bidirectional Project/contract/order links, selected-line set equality, original Company/customer/currency, exact qualified UOM/Item facts and supported draft native snapshot digest. A native custom Link alone never qualifies an order. Reconciliation and source-policy versions enter the watermark. Recognized order standing is an obligation, never a certified/billed floor; no zero-floor inference or accepted-cap relaxation.
