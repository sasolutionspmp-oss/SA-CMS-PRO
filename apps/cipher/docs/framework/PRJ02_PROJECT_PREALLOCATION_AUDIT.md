# Pinned native Project preallocation audit

Read-only source and installed-configuration audit of ERPNext 16.51.0 / Frappe 16.52.0. This does not qualify a Project creation or enable an award writer. The proposed Project stage still needs an actual rollback/notification/search-cache proof under the selected award boundary.

Native create authority for an uncreated document is the supported `frappe.has_permission('Project', ptype='create', user=actor.user)` call with no `doc`. `frappe/permissions.py:138–169` takes the role-permission branch. Passing a particular Project instead invokes its document controller permissions; Cipher's existing Project hook intentionally denies native mutation. The former check neither grants Project read nor permits a generic native insert. The exact factory and current Company delegation authority remain mandatory.

`erpnext/projects/doctype/project/project.py:96–104` validates the template, sends welcome emails for Project users, updates costs/progress and checks dates. `after_insert` at218–224 copies template Tasks, optionally updates a linked Sales Order and grants Project User document shares. The bounded factory must leave `users` empty, `project_template` and `sales_order` unset, use manual progress, and provide only reviewed Company/customer/name/dates and explicit supported defaults. No cost center or template child creation is implied. Native costing reads do not establish an accepted budget or certified financial floor.

Frappe `Document.run_method` (`frappe/model/document.py:1247–1267`) also runs installed hooks, Notifications, Webhooks, Server Scripts and Automations. Installed read-only inspection found no enabled Project Notification, Assignment Rule or Webhook; server scripts were disabled. Wildcard hooks still include workflow, assignment, permission-log and search processing. Installed SQLite search hooks named only ERPNext ItemSearch. These observations are configuration facts, not a guarantee about arbitrary later site customization; the supported creation boundary must refuse unqualified behavioral configuration.

The standard insert has effects outside the SQL savepoint:

- `Document.run_post_save_methods` at1470 invokes `notify_update` unless the supported per-document flag `notify_update=False` is set. `notify_update` at1506–1512 registers realtime publication after commit.
- Global search is called independently at1473. `frappe/utils/global_search.py:242–286` checks the supported site configuration `disable_global_search`, document status and enabled/disabled standing. It has no per-document `ignore_global_search` or deferred option. The audited site had global search enabled.
- Search payload contains doctype, native name, copied `project_name` and Customer search content, title, route and `published=0`. `sync_value_in_queue` at425–432 pushes this directly to Redis; its fallback writes the SQL search index. The background synchronizer at371–422 blindly deduplicates/upserts that supplied content without reloading a committed native row or removing missing names. A rolled-back Project can therefore leave a private copied-content maintenance hint/index row. It is not an opaque ID-only hint.
- Authenticated native `global_search.search` at480–543 loads the real Project title and checks current native document permission before returning a result. A missing rolled-back Project is caught and omitted. It returns no total count. SQL limit/offset precedes permission filtering, so native result-page sparsity remains possible. Guest web search selects published entries; the Project hint is unpublished. This is source analysis, not an actual orphan search qualification.

`frappe/database/database.py:1196–1226` explicitly distinguishes full rollback from rollback to savepoint. The savepoint branch executes SQL and clears value cache; it does not reset `after_commit` callbacks or run rollback watchers. Full rollback resets before/after-commit callbacks and runs rollback handlers. Webhook intents also use a request-local queue plus after-commit flush (`frappe/integrations/doctype/webhook/__init__.py:73–119`); savepoint rollback alone cannot retract them.

No install/migrate flag spoofing, controller bypass, global runtime patch, metadata mutation or configuration change was performed. This source finding is resolved by the selected persistent supported disable_global_search profile and exact callback boundary below; copied-content residue from the new award stage is not tolerated. A SQL savepoint by itself does not remove native cache state. The profile and boundary still require targeted runtime qualification.

## Selected supported profile and remaining prerequisites

Root selected the supported site profile `disable_global_search=True`, rather than a native post-save mixin, temporary command-local configuration toggle or core patch. Deployment/configuration changes remain root-owned. The flag appears at exactly three pinned entry checks: `rebuild_for_doctype` (line72), ordinary document `update_global_search` (line248), and the all-web-pages indexing wrapper (line290). It prevents the ordinary Project/Sales Order insert from adding new global-search hints. Neither authenticated `search` nor guest `web_search` checks the flag; existing index contents remain queryable through their usual permission/publication behavior. Direct lower-level sync/queue/index helpers and the queue-draining synchronizer also do not check it. Existing Redis hints may therefore still drain into the index. Disabling indexing does not erase earlier rows or hints.

Supported cleanup functions are `reset()` (all index rows), `delete_global_search_records_for_doctype(doctype)` (one entire DocType), and `delete_for_document(doc)` (one exact known native identity). They are maintenance operations, not automatic profile effects. No cleanup, Redis mutation or index purge was performed by this audit.

Both native documents require `flags.notify_update=False` for the bounded factory. The native callback profile must qualify or refuse enabled Project/Sales Order Notifications, Webhooks, Assignment Rules, Workflows, Automations and server scripts; it must also keep Project users/templates/preexisting Sales Order links and attachments absent. The installed ItemSearch SQLite hook does not target Project or Sales Order. Sales Order remains a new nonstock draft: no submission, packing/product bundles, stock/warehouse/drop-ship/subcontract behavior, tax/shipping defaults, amendment or quotation-source mapper. The adapter checks persisted tax/packing/stock behavior and exact terms in addition to the financial reconciliation projection.

The installed `CallbackManager` exposes `len`, `add`, `cut(count)` and `truncate(count)` (`frappe/utils/__init__.py:1120–1178`). Backend's literal savepoint boundary must retain previously registered callbacks and remove only the failed award stage's callback tails and owned request-local intents. A savepoint alone does not provide that behavior. The exact profile, callback boundaries, failed-stage queue/callback absence and successful stage still require actual pinned-runtime qualification before award writer activation.

Canonical Cipher search remains the normal product UX. Native Desk global results can become stale because the selected profile stops new indexing without disabling reads of existing rows. This tradeoff is explicit; no native read-disable or automatic cleanup is claimed.
