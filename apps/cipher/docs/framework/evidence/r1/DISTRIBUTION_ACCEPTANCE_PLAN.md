# Independent Company distribution acceptance

This is the acceptance contract; executed outcomes are linked in the
[acceptance status](DISTRIBUTION_ACCEPTANCE_STATUS.md). COM-02 Issue has separate
[actual HTTP proof](company-com02-issue-http.json) and
[current-source/receipt proof](company-com02-issued-source-http.json).
Root coordinated additive metadata, exact policy, explicit Company duty and the
fixed synthetic profile. The [operational report](distribution-operational-acceptance.json)
now qualifies the bounded local queue/recovery and operator-quarantine cases;
actual restored-site and live transport qualification remain separate.
No SMTP, live email, inferred credential or external provider is involved.

Use real cookie/CSRF APIs for immutable instruction creation and the exact
`proposal.distribute.v1` request, canonical-alias self-review refusal, independent
human grant and requester consumption. Validate the actual request/response
schemas. Consumption must atomically create one immutable dispatch and canonical
recipient operations; it cannot claim sink acknowledgment inside that transaction.
Same-person original UUID retries must return the same dispatch and recipients.

The issued artifact and addresses are fixed sources. Recipient IDs derive from
the exact originally issued recipients. A second recipient requires an actual
separately prepared, reviewed and issued successor; a fixture must not append an
address to an existing Issue. Each delivery binds original PDF hash/length,
Issue/instruction/message/profile digests and stable dispatch/recipient key.

Root/backend selected the literal `cipher_distribution` queue, with no consumer
initially, for deterministic staging. Task workers on `short` remain running.
Normal queued workers must not race an independent fault wrapper.
Record any worker hold, controlled fixture lease expiry or fault injection
explicitly; none proves an unobserved production scheduling property. Use the
real worker and independent SQLite subprocess sink. Only the adapter response
boundary is faulted; authority, source readers, grant and database controllers
remain real. An actual persisted sink acceptance must commit independently of
the Frappe transaction before a simulated lost response is raised.
Manual worker proofs do not qualify automatic delivery. A persistent dedicated
consumer and its actual restart/recovery remain separate operational gates.

| Boundary | Required independent observation |
| --- | --- |
| Exact grant | Cookie/CSRF review binds artifact, addresses, message and transport profile; alias cannot independently approve; original UUID yields one dispatch. |
| Lost acknowledgment | Sink commits original PDF and stable key, adapter loses response, Frappe operation becomes Unknown; later same-key readback records the same acknowledgment without another acceptance. |
| Partial recipients | One succeeds, another loses response or refuses before acceptance; recovery never resends the succeeded recipient or changes an address. |
| Frappe lock release | A separate database connection acquires relevant operation/Company/participant/source locks while the actual adapter boundary is held; it rolls back its observational locks. |
| Fence/crash | An expired/superseded old attempt cannot overwrite a newer fence or accept newly after its bounded attempt window. Persistent sink readback survives independent worker/process restart. |
| Current authority | Revoke exact original source/native/actor authority before a new attempt; it refuses new acceptance. Restoration cannot silently alter an immutable failed command or approved mandate. Accepted-but-unconfirmed readback remains observational. |
| Cancel and expiry | No new sink acceptance after current cancellation or durable mandate expiry; previously accepted stable-key acknowledgment can still reconcile honestly. |
| Restore quarantine | Quarantine permits inspection but prevents new worker effects. Redis outage cannot erase authoritative queued/Unknown state or produce a fabricated success. |
| No financial effect | Original Company source scope and Issue/PDF remain unchanged; no Project, Sales Order, invoice, ledger posting or live transmission follows local fixture delivery. |

Bench-native worker probes are separate from HTTP qualification. Preserve first
failed attempts, original request bodies/UUIDs privately, exact source/reload
boundaries and restoration notices. Counts are observations, not padded behavior
totals. The sink database is private and durable; public evidence contains safe
hashes, stable synthetic IDs, state transitions and verified acknowledgments.
