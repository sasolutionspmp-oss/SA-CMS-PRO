# FIN-01 construction contract foundation acceptance

`fin01-native-acceptance.json` records 10 focused exact-value/floor validator
cases and 11 actual native-storage/governance checks on an isolated synthetic
Project. It binds 31 owned source hashes. The first native attempt exposed a
repository argument collision, which was fixed; the second stopped on a harness
assumption about pagination. Both failed logs remain hashed in the report.
The passing run includes independent human Session fixtures, one baseline
consumption, stale-manifest denial, immutable terms/policy/SOV snapshots,
fail-closed accepted cap reduction, stable line increases, current party/source
revocation, disabled-source historical access, off-page party isolation, and
historical receipt UOM lock ordering. Forty-one schema samples validate actual
persisted responses and explicitly reconstructed request shapes; they are not
forty-one independent behavioral tests.

Astra approved the final targeted source and native evidence review. The evidence
was moved unchanged from `r0/` into this R1 directory.

`fin01-http-acceptance.json` records 38 actual cookie/CSRF HTTP requests against
the four public FIN APIs and the shared GOV request/review/execute APIs on
isolated Project `PROJ-0030`. Existing private fixture identities supplied real
login credentials; no credentials or cookies appear in the artifact. Missing
CSRF was rejected before an effect. Eleven actual request/response schema
samples passed. Canonical-person alias retries, changed-payload conflict, stale
version denial, independent outsider denial, Jordan's independent grant, Morgan's
single baseline consumption, and current document/contract duty revocation all
passed. Revocation also denied original source-bearing receipts and consumed
packet/retry access while Project read remained granted.

Independent authenticated bench readback found unchanged row counts across the
12 native financial/activity channels and GL Entry. All installed channel counts
remained zero for the synthetic company. Expense Claim was not installed and is
reported as absent. No submitted transaction, payable, certificate or accounting
entry was created. The temporary native-party read role was removed from Morgan,
the alias, and Jordan, preserving every pre-existing role; isolated Project duty
toggles were restored. Main fixture duties/status/passwords were not changed.
These bench fixture/readback operations are identified separately from HTTP.

The implementation is under
`platform/apps/cipher_aec/cipher_aec/construction_finance/` and
`platform/apps/cipher_aec/cipher_aec/cipher_finance/`. Reproduction procedures are
`tests/test_construction_finance_acceptance.py:run_acceptance` (native) and
`tests/test_construction_finance_http_acceptance.py:run_http_acceptance` (host
HTTP with the private fixture path). The HTTP procedure is deliberately outside
the fresh runner's bench acceptance registry.

The production floor reader remains unavailable. Typed injected floor snapshots
qualify validator behavior only. Baseline acceptance does not establish legal
execution, certification, retainage movement, financial posting, or an external
provider connection. The combined fresh gate remains separate evidence.

`fin01-http-history.json` records the separate final history-privacy regression
following the shared history fix and web reload. Its 15 actual HTTP requests
reuse `PROJ-0030` and existing identities without creating business effects or
Users. Six authorized events become one source-free Contract-created event when
document read is revoked; the exact old authored revision and approval events
are absent for both primary and alias. Revoking the native Customer's Project
association instead leaves one independent document event and hides all FIN and
approval events. Items, exact totals and bounded cursors reflect the same visible
set. Restoration returns the identical original six event IDs and count for both
accounts. The native association and duties were restored and the temporary
source role removed, preserving other roles. The report binds the shared final
history reader/listing source separately; the earlier 38-request FIN/GOV capture
remains intact as evidence before that shared history change.
