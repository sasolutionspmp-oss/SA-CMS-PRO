# Source observations

These observations describe exact Candidate 5 source. They are not runtime findings or requests to change application code.

1. **Offline implementation label differs from the product source.** The [device policy](https://github.com/sasolutionspmp-oss/SA-CMS-PRO/blob/4b884afa21ca1618bd47e2107d8212d261ecc1e9/apps/cipher/platform/apps/cipher_aec/cipher_aec/field_offline/device-policy.json#L3) still says `contract_only_no_browser_vault_or_service_worker`, while the product contains an encrypted browser vault and capture screen. That label does not describe the whole composed interface. It also does not establish service-worker support.
2. **Purge wording and page access differ.** [The screen](https://github.com/sasolutionspmp-oss/SA-CMS-PRO/blob/4b884afa21ca1618bd47e2107d8212d261ecc1e9/apps/cipher/product/src/FieldOffline.tsx#L114) says local removal needs no sign-in or decryption. The vault operation itself has no authentication dependency, but [the shell](https://github.com/sasolutionspmp-oss/SA-CMS-PRO/blob/4b884afa21ca1618bd47e2107d8212d261ecc1e9/apps/cipher/product/src/App.tsx#L195) displays this page only with an authenticated session and authorized Company context. A signed-out purge entry is not established.
3. **Encrypted retention is not a complete reload journey.** [The vault](https://github.com/sasolutionspmp-oss/SA-CMS-PRO/blob/4b884afa21ca1618bd47e2107d8212d261ecc1e9/apps/cipher/product/src/field-offline-vault.ts#L90) can retain encrypted data, while [the page](https://github.com/sasolutionspmp-oss/SA-CMS-PRO/blob/4b884afa21ca1618bd47e2107d8212d261ecc1e9/apps/cipher/product/src/FieldOffline.tsx#L18) starts with an empty registration UUID and [the shell](https://github.com/sasolutionspmp-oss/SA-CMS-PRO/blob/4b884afa21ca1618bd47e2107d8212d261ecc1e9/apps/cipher/product/src/App.tsx#L178) needs session/Project context. Retention alone does not establish offline cold-start, automatic profile discovery or unsealed-form recovery.
4. **The stale-record recovery instruction may leave Save disabled.** [The editor](https://github.com/sasolutionspmp-oss/SA-CMS-PRO/blob/4b884afa21ca1618bd47e2107d8212d261ecc1e9/apps/cipher/product/src/QualitySafetyEditor.tsx#L25) disables saving after a 412 response and directs Cancel/refresh. [Cancel and refresh](https://github.com/sasolutionspmp-oss/SA-CMS-PRO/blob/4b884afa21ca1618bd47e2107d8212d261ecc1e9/apps/cipher/product/src/QualitySafety.tsx#L37) do not clear the mutation error; [the mutation helper](https://github.com/sasolutionspmp-oss/SA-CMS-PRO/blob/4b884afa21ca1618bd47e2107d8212d261ecc1e9/apps/cipher/product/src/useMutation.ts#L13) clears it when another request starts. This is a source observation, not a reproduced runtime result.
5. **Incident evidence has two visible limits.** [Decision and closure selectors](https://github.com/sasolutionspmp-oss/SA-CMS-PRO/blob/4b884afa21ca1618bd47e2107d8212d261ecc1e9/apps/cipher/product/src/QualitySafety.tsx#L40) offer evidence from the current revision, with no new private-upload control there. Elsewhere, [private upload success](https://github.com/sasolutionspmp-oss/SA-CMS-PRO/blob/4b884afa21ca1618bd47e2107d8212d261ecc1e9/apps/cipher/product/src/QualitySafetySources.tsx#L20) says the file was saved and attached, while [incident ingestion](https://github.com/sasolutionspmp-oss/SA-CMS-PRO/blob/4b884afa21ca1618bd47e2107d8212d261ecc1e9/apps/cipher/platform/apps/cipher_aec/cipher_aec/quality_safety/README.md#L11) separately needs current content rights. Upload confirmation and readiness for incident use are distinct.

No application changes, runtime checks or accounting actions were performed in this review.
