# DOC-03 Project backend handoff

This is a working Project increment of original DOC-03/C20, not completion of that package. It adds canonical immutable rights/library/adoption/issued-set/internal-transmittal/evidence records over existing Document Revision/File bytes. It does not duplicate artifact storage or change financial, schedule, contract, engineering-check, seal or external-delivery state.

Use `cipher_aec.document_control.api` and generated `src/api/document-control.generated.ts` (Dc*). POST: `set_rights`, `create_library`, `revise_library`, `create_adoption`, `create_issue_set`, `create_transmittal`, `record_evidence`. GET: `get_record`, `list_records`, `list_people`. Requests carry company/project and operation UUID only where generated; author/person/session come from the server. Reads return `{record, record_digest, library_current}`; the last value is null where inapplicable, and for adoption/library sources checks both the library head and native original Document working head. Historical facts stay readable if current original-source rights permit. Pages use bounded limit25, count_mode=none, total=null and authority-bound signed cursors; no total/exhaustive/performance qualification.

`set_rights` takes document_id, latest rights-record digest (null for first), and a closed definition: ingest_allowed/read_allowed/distribute_allowed, rights_holder, allowed_purpose, restriction, rights_basis, valid_from/valid_until (explicit nullable ISO dates, inclusive UTC), and evidence_artifact `{revision_id,source_sha256}`. Existing evidence must be a distinct retained Project Document; actual bytes/current access are checked and the expanded immutable canonical artifact is retained in the policy. Evidence revisions may become historical; their content never changes with a successor. Cyclic/deep evidence fails closed. Current dates, ordinary Project/native source access and original evidence access gate ingestion, retrieval and distribution independently. Rights basis is an authored declaration, not a verified legal license. A dedicated rights manager can revoke retained sources after Project closure. Use bounded rights history filtered by parent document ID; server admission owns current-version checks.

Library definitions include title/category (specification/contract_clause/reference), discipline, ownership, tags and change_reason, with one exact existing artifact. Library successors preserve originals. `create_adoption` prepares a request with exact library revision/digest and purpose/target_locator/change_reason; its independent effect creates an immutable adoption over the same original bytes. `create_issue_set` groups exact artifacts plus exact adoption IDs/digests. Issue status is documentary issuance after independent review, not professional engineering issue/seal. `create_transmittal` takes exact authorized issue ID/digest, canonical scoped recipient usernames, purpose and required_response. Recipient/source access and identity are checked again at authorization time. Distribution is internal record creation only. `record_evidence` reports received (distribution, intended recipient only) or execution evidence (adoption); both are documentary reports and commercial_execution=false.

Three literal independent approval actions: document.issue.v1 (issue_set), document.library.adopt.v1 (adoption_request), document.transmit.v1 (transmittal). Generic GOV03 request/decide/execute supplies `cipher.document.approval.v1` packets. Join the original domain subject/sources/effect/summary exactly. **manifest_hash is the opaque hash of the full outer GOV03 authority manifest; it is not digest(review_manifest).** Preserve its exact value across decisions/execution and mounted original-UUID recovery. Backend receipt checks already use the full outer hash and immutable grant consumption. Old Company and engineering approval pairings are unchanged. Existing ENG01 internal distribution additionally honors a present content-distribution restriction; no-policy behavior is preserved.

New Project abilities: document.control.read/write/review, document.rights.manage, document.issue/adopt/distribute. No default/seeded grants, Company abilities or native roles are added. `list_people` supplies current scoped canonical choices using document.control.read without RFI duties. Native DocType JSON/read/write routes are closed; exact API/controller private plans own writes. Supporting rights graphs are bounded to64 documents/depth8, and generic native policy admission has a500-head hard ceiling (fail closed); these are admission limits, not truncation or performance claims.
