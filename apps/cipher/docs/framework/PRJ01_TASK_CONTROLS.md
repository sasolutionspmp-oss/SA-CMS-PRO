# PRJ-01 ordinary Task controls

Source implementation and 24 host contract checks are verified. The added native integration cases require the root-owned serialized Frappe/MariaDB qualification run before this slice is called locally verified. No live business system is qualified by host checks.

ERPNext Task remains the work record. One ordinary Task can have one governed canonical Cipher Person assignment, backed by an ordinary native ToDo. Account aliases are resolved on the server; callers never choose a native User. Exact current Project access and native read permission are checked for the person selected at assignment time. Current `task.assign` and `task.update` duties are separate from `task.create` and Company authority.

| RPC in `cipher_aec.api.v1` | Contract |
|---|---|
| `task` | GET company, project, task; current scoped Task |
| `task_choices` | GET company, project; current capabilities, eligible canonical people, allowed statuses |
| `assign_task` | POST company, project, task, assignee_person or explicit null, expected_version, operation_id |
| `update_task_status` | POST company, project, task, status, expected_version, operation_id |

Every command requires the matching Idempotency-Key and session CSRF token. Results retain the existing `{task, project_version, operation}` shape. New assignment/status commands use `TaskControlResponse` with `CurrentTask`, requiring canonical `assignees` and `assignment_conflict`. Those additive fields remain optional in historical `Task`/`CreateTaskResponse` because original immutable pre-feature receipts must remain valid without rewriting their result bytes. Task version tokens bind reviewed native facts and the native timestamp: upstream overdue and assignment updates can change facts without advancing `modified`.

Manual targets are native `Open`, `Working`, `Pending Review`, and `Completed`. Complete sets the server actor as native completed_by, retains native completion date/progress semantics, and closes the exact governed ToDo. Reopen is `Completed` to `Open`; native completion fields clear, and closed ToDos remain historical. Reassignment/unassignment cancels only the current owned ToDo. Derived `Overdue`, templates, cancelled work, groups, and parent-linked Tasks require their separate workflow. Native dependencies still prevent completion until resolved.

The service refuses unexplained, duplicate, incomplete, or mismatched native assignment facts. It preserves them for administrator reconciliation instead of adopting or erasing them. Generic Task writes and native ToDo insert/save/cancel/delete/retarget paths remain protected; unrelated personal ToDos retain native behavior. Ordinary product users read Tasks only through the canonical Task list/detail APIs. Their raw native Task resource route is denied because Frappe field-level reads do not filter hidden permlevel-zero fields or the native `_assign` User list. Administrator/System Manager native tooling retains its existing upstream access; other native resource admissions are unchanged.

Supported native Task controller flags `from_project` and `ignore_reschedule` prevent a Task-only command from silently completing/reopening its Project or rescheduling other Tasks. The command advances Project modified explicitly, without changing governed Project status/progress, accepted commercial records, award records, or money. ToDo Document insert/save maintains native assignment comments and `_assign`; the assignment helper is deliberately not used because its notify flag does not suppress notification, implicit sharing, or follow behavior in the pinned runtime.

Installation adds three hidden, read-only, no-copy Task Link fields through the supported Custom Field API: `cipher_assignee_person`, `cipher_assignee_user`, `cipher_assignment_todo`. `cipher_aec.projects.install.metadata_status` is the read-only upgrade proof. Missing metadata fails closed. Migration grants no duties and rewrites no existing assignments. Saved human trials need an explicit operator duty extension; they must not be reseeded.
