# Isolated award prerequisite procedures

Source authored; runtime unexecuted. Root selects the immutable disabled/enabled application epochs, disposable container, retained synthetic site, source release manifests and serial User/Auth slot. No procedure here selects an epoch, changes site configuration, enables an action or calls `seed_synthetic`. Existing main-site fixtures are not prerequisites.

The entry module is `cipher_aec.tests.test_award_prerequisites`. None of its functions is named `run_acceptance`. Native setup is separate from actual cookie/CSRF review. Do not use the older in-process `NativeRPC` session fixture for baseline, Issue or award review.

## Required operator inputs

Supply an explicit `repository` visible to the process, `release_manifest`, and new private mode-700 directories. A release manifest has schema `cipher.award.acceptance-release.v1`, an operator-declared `runtime_epoch`, and exact repository-relative `source_sha256` entries. It must bind the actual served product and fixture source epoch, not a guessed current disk snapshot. Native recovery retains the original release paths from the setup intent; later HTTP stages bind their own released epoch.

The runtime prerequisites are root-installed current metadata, synthetic site mode, supported Company/ERP setup, existing qualified USD policy, enabled Company `estimate.accept.v1` and `proposal.issue.v1` policies, and the reviewed native profile/configuration. Canonical source use requires the site's existing explicit synthetic `cipher_allow_unscanned_documents` allowance; this never qualifies a clean antivirus scan. The award action remains disabled during prerequisite preparation. Root backs up and inventories the site first. The fixture adds only unique owned identities, Companies, native masters, roles and scoped duties. It never resets a pre-existing user's password or edits an unrelated native accounting target.

## Native setup and exact recovery

1. In the isolated site's fresh Administrator bench invocation, call `prepare_award_prerequisites(private_directory, repository, release_manifest)` in the exclusive User/Auth slot. It records broad exact table hashes and private **full original Account rows before** supported Company/chart creation. It then calls the existing supported Company fixture with `require_historical=False` and an optional setup journal. Two unique Companies and identities are created; the unrelated Project-only control is explicitly separate from the Company award destination.
2. Before the first setup commit, `base-native-command-intents.json` stores the exact count-UOM registration and Project-control Task UUID, body, actor and expected native Project version. New credentials are durably saved to the original private Company-chain manifest before that commit. The optional hook leaves existing default fixture callers unchanged.
3. If interrupted after that commit, use **only** `resume_award_base_fixture(private_manifest, setup_directory)` with that original newly written manifest. `setup-intent.json` records the pre-existing manifest filenames so root can identify the unique new file without guessing or printing its contents. Recovery rechecks the stored source manifest paths and exact original release identity before any native effect; replacing a manifest/epoch at those paths refuses. Recovery never allocates another Company, User, Project or command UUID. It can recover the `prerequisites_created` phase, replay the same native operations and publish the ready manifest/result. A failure before the original identity commit cannot be repaired by creating replacement identities through recovery.
4. Call `complete_award_prerequisites(private_manifest, setup_directory, repository, release_manifest)` with the same ready manifest. A resumed completion must match its original source binding and fixture ID. It adds native read/create prerequisites only to the newly owned roles, a reviewer cost-read duty, separate initial-team Company eligibility, explicit qualified labor/equipment UOM registrations with durable original UUIDs, and the supported Company delegation policy. It installs no approval action/Grant. Output is `native-prerequisites.json`.
5. Run `inspect_award_setup_preservation(private_manifest, setup_directory)` in a separate fresh operator invocation. It preserves exact old Account column differences and interval ancestor comparisons. New Account rows outside the exact two fixture Companies, deleted original rows, changed non-tree columns, changed ancestors, or other unexpected original business changes remain unresolved. Full-row Account preservation is reported separately from any attributed `lft`/`rgt` maintenance. No repair/rebaseline occurs. Root retains its independent backup/readback too.

The returned credential manifest path is a **private file path only**, never credential values. Root securely copies it for host-side HTTP with mode 600. Native functions use the original site-private path; HTTP functions use the copied path containing the same fixture data.

## Real HTTP stages

Both stages require `private_manifest`, `native_context` (the saved `native-prerequisites.json`), `repository`, `base_url`, `private_directory`, and `release_manifest`. Supply optional `host_header` with root's exact isolated site when using the directly published backend; never assume the main proxy or default site routes to the retained CI site. The composed HTTP probes accept the same override. Set `resume=False` for a new stage directory, or `resume=True` only for that exact original directory. Each logical command saves its role/method/body/UUID before network transmission. Known completed responses are reused as stage data; unknown sends retain the original UUID/body. Current canonical source reads still run. Reports explicitly list reused steps and new request timings.

`build_award_manual_baseline_http(...)` uploads actual raw manual source bytes, creates a same-Company Pursuit, native-source-priced mixed assembly and estimate, then requests, independently grants through the reviewer's actual cookie/CSRF session and consumes `estimate.accept.v1`. The author's alias is refused as reviewer. The authored calculation has assembly material 5.00 + labor 4.00 + equipment 3.00, a separate material 1.25, indirect 1.33 and contingency 0.42: accepted cost **15.00**. An excluded alternative is priced at 5.00 and remains unfunded. Output is `manual-baseline-context.json`. No generated input or calibrated geometry is asserted; the generated-input gate remains false.

`build_award_issue_and_mappings_http(...)` additionally requires `baseline_context` from that stage. It creates a legitimate proposal, actual canonical prepared PDF and real independent `proposal.issue.v1` Grant/consume. The separately authored selling value is **30.85**. It creates exact canonical cost-code/type revisions over existing owned leaf Cost Center/expense Account targets, explicit WBS/allocations and a bounded team. It then creates the canonical handoff and saves a real immutable draft award plan while execution remains disabled. Outputs are:

- `authored-context.json`: Company, actual Issue, explicit authored definition, native/source references and initial-team login role.
- `company-plan-context.json`: Company, Issue, exact saved `plan`, `version` and `handoff`.
- The same original credential manifest path, without credential values.

The requester is outside the initial team. The separate `project_only` fixture identity supplies the canonical team Person; it receives Company eligibility only during setup and exact Project `project.read`, `wbs.read`, `budget.read`, `contract.read` only through a later independently approved award. Its existing unrelated Project control is unchanged. No Company source/write ability or creator Project duty is inherited.

## Disabled and enabled epoch handoff

The disabled-epoch `run_award_disabled_http` consumes `company-plan-context.json`; root pairs it with exact native before/after inventories to prove no allocation. Preserve that report before selecting the independently reviewed enabled epoch. The source builder does not request or execute an award.

Later `run_award_grant_http` uses the exact saved plan under root's enabled release and reserves an execute body/UUID. Native rollback probes and actual execution consume that original context at separately released boundaries. UI receives exact saved handoff/plan IDs and may author a distinct legitimate successor before review; it must not recreate prerequisite commands or reuse the grant subject silently. The private manifest/context paths are shared by path only after root releases access.

Composed monetary adoption, native factory effects, same-connection rollback, independent readback, callbacks/queue/cache observations, concurrency and FIN recognition remain separate pending runtime gates. The local artifact/calculator tests qualify fixture behavior only.
