Active preparation following the controls foundation review. This document defines future native and HTTP qualification; none of these composed cases has run. Award activation, metadata installation, identity provisioning and runtime execution require root's separate release. The reviewed controls foundation, native adapter unit tests and existing COM Issue evidence do not qualify an award execution.

The implementation boundary is [the handoff contract](PRJ02_HANDOFF_SCHEMA.md), [FIN admission](PRJ02_FIN_ADMISSION_CONTRACT.md) and [the native callback audit](PRJ02_PROJECT_PREALLOCATION_AUDIT.md). Existing Company and Project records remain controls, not mutable fixture inputs.

## Fixture and execution contracts

Use one isolated synthetic site approved by root. Provision identities in one serialized setup slot, without reseeding an existing site or resetting existing passwords. Record exact source hashes, installed metadata, profile values and baseline inventories before the first command. All command UUIDs and exact bodies go into a private mode-600 journal before transmission. Credentials and raw site backups stay outside repository evidence.

The principal positive fixture has an author and same-Person alias, an independent reviewer, a separate canonical team member, and an outsider. The author/delegator is deliberately absent from the reviewed Project team. The team member receives only the reviewed exact Project abilities; no role expansion, blanket duty or implicit creator access is permitted. The author retains explicit Company award/delegation/source/native authority. Review uses a real interactive cookie/CSRF session; a bench request cannot impersonate an interactive independent Grant.

Reuse or create an actual immutable Company Issue through the qualified COM path, with its accepted baseline and canonical PDF bytes. Bind an explicit real Customer, eligible nonstock sales Items, qualified UOM/Currency, selling Price List, existing leaf Cost Centers and eligible expense Accounts. Native masters are fixture prerequisites created through supported controllers, never a product fallback. Baseline setup and any native chart/tree changes receive their own preservation inventory.

The accepted cost fixture includes an included mixed assembly, a distinct included line, an excluded alternative, and separate indirect and contingency adjustment UUIDs. It provides a meaningful difference between accepted cost and issued selling value. The authored WBS has a root and leaves, with accountability naming only reviewed team members. Each accepted component and adjustment has one exact allocation; no split allocation is admitted.

Use the current fixed `cipher_aec.awards.api` contracts:

Every POST uses the matching `Idempotency-Key` and actual CSRF token. Record schema-qualified response samples and per-request durations independently from fixture or traversal duration. Recover an unknown outcome with the original UUID/body. A new UUID is not a recovery mechanism.

The native fixture entry will have a distinct name such as `run_award_composed_acceptance(private_manifest, fixture_context)`, with explicit site-bound arguments. It must not be silently discovered as canonical no-argument `run_acceptance`. A self-contained fresh-site wrapper requires its own reviewed prerequisites before later runner registration.

## Rollback observation contract

Record fixture-owned exact IDs plus whole pre-existing row hashes. A rollback pass requires a new database connection after the command closes, not a query through its old repeatable-read snapshot. Native naming-series gaps are allowed and disclosed. No other durable result is exempted.

The inventory includes Project, minimal Project profile, Task, ToDo, DocShare, exact Project duties, WBS nodes, budget versions/lines, FIN contracts/revisions/SOV/terms/policies, Sales Order/items/Payment Schedule, handoff/adoption/line projections, command receipt, approval consumption, award history, native Version, File, Document Follow and Item Price. File evidence contains private row hashes, never file bytes or credentials. Success requires no new Version/File/Document Follow/Item Price rows; the supported native order has exactly one default Payment Schedule child. Refusal leaves none of these new rows. Pre-existing review Grant/packet and authored plan remain unchanged on an execute refusal; execution must not erase legitimate prior committed steps.

Observe callback manager prefixes/tails and local webhook/realtime queues at the controlled seam. Inspect native notification/business integration intents, after-commit RQ publication and global-search copied payload/index state before and after the failed request. The selected persistent `disable_global_search=True` profile must already be active and checked before allocation. No temporary toggle, discarded unknown cleanup callback, missing-name search filtering or opaque search exception qualifies rollback. Unknown rollback callbacks must use supported full rollback and actual cleanup.

Exact pre-existing native authoritative columns are compared separately from supported fixture Company/chart setup tree maintenance. Any Account `lft`/`rgt` change remains a disclosed full-row preservation difference requiring exact attribution; full-row preservation cannot be claimed from equal non-tree columns alone.

## Authored procedure status

The opt-in fixture is now authored in `cipher_aec.tests.test_award_composed_acceptance`; it has no canonical `run_acceptance` entry. `run_award_plan_http` authors the explicit supplied Issue/definition, checks alias replay, changed-payload conflict, stale version and duplicate aggregate refusal. `run_award_disabled_http` uses that legitimate plan under the original disabled source epoch. `run_award_grant_http` reserves an execute UUID after actual cookie/CSRF request, author-alias refusal and independent Grant; it never executes. `run_award_execute_http` consumes only that retained original request and checks replay plus excluded-requester destination denial. Each stage writes exclusive private artifacts and requires a root-supplied served-source release manifest.

`capture_award_inventory` records whole exact parent-table row hashes, including native Version and notification/integration tables. `compare_award_inventory` reports all inserted, deleted and changed identities without allowed-table exemptions. The native `run_award_rollback_probe` accepts only a preexisting real Granted context, a specific expected refusal contract and root's source release manifest. It observes the real allocation, or injects a fault only after the exact real execution receipt is inserted; it never substitutes source authorization, an interactive review, profile validation or an award effect. Immediately after the caught refusal, a read-only helper inventories the same executing connection and requires exact baseline equality BEFORE any harness rollback. Callback prefixes and local webhook/realtime intent prefixes are checked by object identity in the original connection. A subsequent separate native inventory and external queue/search observation remain required; probe completion alone is not a rollback qualification.

Five local artifact-integrity tests cover preservation of original unknown intents, exact old-row versus new-fixture differences, release-source drift/path containment, a real SQLite transient row that must fail before harness cleanup, and callback objects with misleading equality. They do not qualify any HTTP call, native award, callback profile or composed adoption. All runtime procedures remain unexecuted pending source review and root's named isolated-site release.
