# Cipher product interface

Fresh React/TypeScript/Vite application using SAP UI5 Web Components for React and the standard Horizon theme. It implements the initial project/document/Ricky workspace against the authenticated `cipher_aec` Frappe APIs. It imports no prior Cipher UI or engine code.

Run Node 22.13 or newer (or Node 24):

```sh
npm ci
npm run generate:api
npm run typecheck
npm run build
npm run test:contract
```

`npm run dev` starts port 5180. With `CIPHER_BACKEND_URL=http://127.0.0.1:18881`, the development server proxies `/api` to Frappe. Users sign in through the in-app UI5 form using the real Frappe `/api/method/login`; profile sign-out uses `/api/method/logout`. No credentials are embedded. Deploy `dist/` behind the same-origin application gateway with SPA fallback for `/projects`, `/documents`, `/work`, `/estimates` and `/connections` (including nested project estimate routes). The gateway must forward these native auth endpoints plus the explicit product methods, session cookies and CSRF/idempotency headers. Backend permissions remain authoritative.

The normal application never loads sample data or substitutes fixtures after connection failures. Tests intercept the documented RPC methods with **explicit synthetic contract fixtures**, kept exclusively under `tests/`. The table regression measures rendered header/body column boundaries at full width and after opening/closing Ricky; task and document tables use official UI5 `Table` composition with a shared column layout. Those tests verify client behavior, not a connected model, ERP persistence or provider acceptance. Screenshots named `synthetic-contract-*` are test evidence only.

For separately authorized read-only verification against the actual running Frappe site, `node scripts/connected-readonly.mjs` privately reads `CIPHER_RUNTIME_MANIFEST` (default `/tmp/cipher-r0-runtime/fixture.secret.json`) and uses `CIPHER_RUNTIME_URL` (default `http://127.0.0.1:18880`). It records screenshots under `test-results/connected-runtime`, signs in without logging credentials and performs no business writes. Run only once the shared synthetic site is ready; do not race database reset/migration tests. The separately coordinated `scripts/connected-approvals.mjs` uses private primary/reviewer fixture accounts in separate browser contexts to exercise real status-change requests, independent grants and execution, then restores Open through another independently approved packet. It performs business writes and must run only in the runtime owner’s assigned mutation slot.

Implemented: in-app sign-in/sign-out; company/project context; filtered sortable project register; signed server-cursor paging for projects, tasks and activity; project ObjectPage with Tasks, Documents and Activity; normal task creation with opaque source version and stable retry UUID; project approval inbox with exact status-change packets, independent review, separately authorized execution, withdrawal and decision history; original-byte document upload with SHA-256; revision/page-bound safe text preview and authorized original download; model availability, contextual questions, persisted run polling/reload, source citations and reviewed task proposals. Unavailable-model states preserve manual business work. Project-specific capabilities control visible actions; all effects use the same backend domain services. Client name/status filters apply to the loaded register page and say so when additional pages exist.

Estimating adds a scoped estimate register, explicit-currency draft creation, immutable revision/snapshot inspection, exact decimal text line editing, atomic tab-separated paste, qualified source/unit selection, indirect/contingency inputs, server calculation, same-operation unknown-result recovery, preserved stale-source inputs with explicit reviewed rebasing, and predecessor comparison by stable line ID. Sources open their actual cited revision text without leaving the editor. All totals and rounding results come from saved server snapshots. Source-library creation and award are not exposed by the estimate editor; commercial Issue uses the separate exact-PDF review described below. Project calibrated takeoff and Company baseline acceptance are described below.

Create and calculate recovery retain the exact original payload and operation UUID after connection loss, server errors, or malformed successful responses. A definitive first-attempt rejection unlocks correction. Once an outcome is unknown, later failures (including receipt-access denial) retain the snapshot and edit lock until an authoritative successful receipt resolves it; the create dialog also prevents cancel and Escape dismissal. These pending snapshots live only in the mounted dialog/workspace. Navigation, remount, page reload or browser restart loses the client snapshot; recovery across those boundaries is not implemented. Server operation receipts persist independently.

The core API types are generated from `../platform/apps/cipher_aec/cipher_aec/api/schema.json`; the generated file records its schema digest. Estimating types are separately generated from `estimating/schemas/api-v1.schema.json`; `npm run generate:api -- --check` verifies every generated artifact without modifying files. Adjacent document/Ricky interfaces follow those module owners' explicit R0 contracts. Every dependency and the lockfile are pinned. Framework assets remain provided by UI5; no SAP logo is used.

Limits: this is an incrementally qualified ERP/CMS workspace. Finance, field and later engineering flows remain outside this UI slice. It does not claim SAP S/4HANA functionality, a connected existing Ricky model, antivirus/OCR, live accounting or offline financial authority. Document extraction/scan status comes from the server. No trained model, CAD tool, payment provider or external delivery is simulated in the normal UI.

The current workspace includes Company commercial pursuits/proposal drafts, Company source documents and estimate drafts, Company approval review, and Project PDF takeoff in the same Horizon shell. Company routes call their explicit `company_api`/Company approval services and never construct a placeholder Project or serialize Project/scope override parameters. Native selectors reuse current permitted Customer/Lead, currency, selling price list and qualified UOM records. Commercial rates/quantities remain exact strings; saved totals belong to persisted native Quotation revisions. Commercial revisions can pin exact Company source pages and an accepted baseline for the same pursuit and currency, using server-issued citation and acceptance digests.

Project drawing takeoff renders authorized stored PDF bytes after matching their SHA-256 to the selected source revision. PDF.js inverse viewport mapping handles the CropBox, native/view rotation, zoom and CSS scaling; DPR only scales the backing canvas. Pointer picks are authored six-decimal coordinates, with exact coordinate editing, not automatic geometry detection. Calibration needs two anchors, an explicit known length and independently reviewed unit relations before calibrated measurement. Server records own quantities and arithmetic bounds. Manual quantities carry no calibration claim. Subsequent exact estimate-line evidence binding preserves the original authored calculation; drawing replacement exposes stale-use impact without repricing saved snapshots.

The PDF renderer is pinned to `pdfjs-dist@6.4.299` (upstream commit `d0991a0d53f3bb3a7307e3b83f279c1d117aafb3`, [Mozilla PDF.js](https://github.com/mozilla/pdf.js)). The engine is Apache-2.0. Supporting fonts, codecs and color profiles retain their separate upstream notices, including PDFium/Foxit terms, the Liberation font license and exceptions, codec notices and CC0 profile terms; they are not all relicensed Apache-2.0. `scripts/copy-pdf-assets.mjs` copies unmodified pinned distribution assets and their license files to `public/pdfjs/` during dev/build. The generated asset directory is ignored in Git and recreated from the lockfile. The worker is bundled locally; there is no external document upload or CDN dependency. The gateway must serve emitted `.mjs` workers as JavaScript with the normal same-origin access rules.

`npm run generate:api -- --check` now checks all nine artifacts: core, Project EST, COM, Project takeoff, Company DOC, Company EST, fixture distribution, Project controls and award. Contract fixtures remain exclusively under `tests/`; connected scripts create uniquely named synthetic records through actual Frappe. `scripts/connected-takeoff.mjs` reads original control fixtures, writes only its own drawing/set/calibration/estimate, independently reviews scale, saves measurement/binding and replaces only its own working drawing. Native permission or MIME preflight failures are recorded as blocked attempts, not successful viewer qualification. All new mutation recovery retains the original in-memory payload/UUID, validates matched receipts and subject lineage, survives later denials, and remains limited to the mounted view. Source upload recovery sends retained bytes without reading the local File again.

The saved measurement panel uses compact UI5 Text/status composition. Display strings may trim insignificant trailing decimal zeros; exact amount, precision, unit identity and source hashes remain in Source details. Revision binding chooses actual authorized saved revisions (current, then bounded predecessor loading through at most100 records), and line labels include actual stored unit metadata. Impact labels read the exact permitted immutable measurement/line records; missing access never substitutes a guessed description. Private pre-send journals in connected scripts are qualification tooling only, not product durable recovery.


The commercial proposal ObjectPage supports exact PDF preparation with intended recipients and cover text. Those inputs become immutable for the selected saved proposal revision. The server owns the revision digest and canonical PDF document/revision; the viewer verifies authorized stored bytes against the returned SHA-256. Independent Issue review opens the exact PDF in the approval manifest, with its original recipients and cover, without resolving a later proposal head. Invalid manifest lineage disables new approval. Explicit403/404 output refreshes suppress cached prepared content and Issue controls while retaining any original mounted mutation recovery. Issue records a native draft snapshot; the historical fact “Issue did not send” is distinct from later distribution. The linked distribution workspace authors immutable fixture instructions for all issued recipients or an exact selected subset using server-issued recipient IDs. Saved instructions and dispatches remain discoverable from the issued record. Independent review opens the exact issued PDF, message and recipient subset before separately authorized queueing. Current dispatch readback distinguishes queued, unknown, partial, stopped and verified local acknowledgments. Verification requires the server-issued expected logical key and payload hash for each recipient; historical embedded receipts without those fields remain unverified until a current read. Stopping remaining work preserves completed acknowledgments and warns that in-flight work may complete. Configuration alone does not claim a running worker. No live external transmission or worker administration controls are exposed.

`node scripts/connected-com02.mjs` qualifies actual Company source/baseline attachment, prepared PDF bytes, independent review and separate Issue execution against owned synthetic records. It writes exact mutation payloads and keys privately before sending, records only their hashes in shareable evidence, and captures desktop/tablet/phone views. This tooling journal does not add application recovery across remounts or browser restarts. Connected evidence remains separate from the synthetic browser contract fixtures.

`node scripts/connected-distribution.mjs` uses an explicitly supplied qualified two-recipient Issue ID (`CIPHER_DISTRIBUTION_ISSUE_ID`) to prove exact subset selection, saved-instruction rediscovery, independent PDF/message review and separate queue authorization through the actual UI. It never starts a worker or changes transport configuration. After the runtime owner qualifies worker processing, `CIPHER_DISTRIBUTION_READBACK=<verification.json>` runs a read-only continuation against the same dispatch. These scripts require the runtime owner’s quiet window and retain a private before-send journal; any unresolved attempt must be reconciled before another key is used. Fixture acknowledgment is local synthetic receipt evidence, not external delivery.

Company approval inbox pages request ten records with `count_mode=none`; they do not imply an exact total. Copyable review links use `/company/work/{packetId}?company={encodedCompany}`. The application validates that requested Company against the current session's Company scopes and choices before reading the packet, preserves the query through in-app sign-in, and reports unavailable Company context instead of falling back to another Company. The exact-task route reads only that packet and its authorized review sources, with no inbox request. Current denial removes review actions; mounted unknown-result recovery retains its original snapshot and disables navigation. This route does not itself qualify normal inbox latency.

`scripts/connected-com02-execute.mjs` continues only the explicitly preserved Granted Issue context. It verifies the original packet, manifest and PDF, journals one still-unattempted execution before sending, and refuses request/Grant repetition. It does not automatically retry an unresolved execution. The earlier failed inbox capture and its completed commands remain historical evidence.


The Company award draft workspace is linked from an exact issued proposal at `/commercial/issues/{issueId}/award?company={encodedCompany}`. It preserves the immutable Issue/PDF and accepted estimate lineage, separates frozen selling lines from accepted cost allocations, and authors explicit existing Customer/Item mappings, WBS, cost revisions and canonical initial team. Source-specific input qualification and action availability come from the server. The author is not implicitly included in the destination team. Server checks do not write; saved plans use opaque versions, preserved stale inputs and explicitly reviewed rebasing. Independent review displays the original issued PDF, bound evidence, exact team and the fixed native draft schedule: one 100% row due on the reviewed transaction date, without an inherited template, discount or paid amount. This does not interpret free-text proposal terms or authorize billing/payment.

Award request/execution controls require the literal server availability and current capabilities. A matched completion validates the original immutable review, latest independent Grant, plan, adoption and native draft identity; current destination Project access is read separately. A Company requester outside the approved initial team sees authorized Company outcome references without inferred Project content. These new award screens currently have explicit local browser-contract qualification only; native execution and actual connected visual qualification remain separate release gates. Mounted original-request recovery survives ambiguous or mismatched successful responses and later current-access denials; it does not persist across navigation or reload.

Company cost setup at `/company/costs/codes|types` provides normal canonical code/type creation and successor authoring using existing leaf Cost Centers or expense Accounts. The dated register distinguishes the effective revision from a newer authoring head. Historical facts remain visible without an eligibility claim; locked server plan validation decides new use. Read access permits selection/inspection, while master authoring requires separate `project.cost.write`. Successor receipts bind the original parent revision and next revision number, and a definitive stale version preserves inputs until explicit current-head review. The picker opens scoped setup in a separate tab so an award draft can remain mounted.
